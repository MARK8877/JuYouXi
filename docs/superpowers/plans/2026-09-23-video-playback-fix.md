# 视频流播放地址修复计划

## 目标

修复视频流页面因剧库列表只返回剧集元数据、未返回 `videoUrl` 而提前显示“本集没有可播放的视频地址”的问题。复用现有 9000 播放服务的会话协议，让视频页按剧集打开播放会话，再解析首集 HLS 地址并循环播放。

## 边界

- 保留 9010 作为剧库元数据接口，新增独立的播放服务地址（默认 `http://127.0.0.1:9000`，可由 `PLAYBACK_BASE_URL` 覆盖）。
- 只新增播放会话/分集流客户端及视频页接入，不修改后端服务、不伪造视频地址。
- 播放服务失败时保留明确的可重试错误态；预览模式继续显示无真实视频的预览占位。
- 复用已有选集页；当列表没有 episodes 但服务返回 episodeCount 时，用轻量分集项展示选择，不把未知地址当成可播放地址。

## 实施顺序

1. 先增加播放响应解析与 API 契约测试，验证 session、分集和 HLS URL 字段。
2. 增加 `PlaybackSession`/`PlaybackStream` 模型及 `LibraryApi` 播放方法。
3. 将视频页从“直接读取 episode.videoUrl”改为“直接地址优先，否则打开会话并请求 HLS”，管理 session 生命周期与选集切换。
4. 让详情选集弹窗使用服务分集或 episodeCount 生成的轻量选项。
5. 运行 `dart analyze .`、`flutter test`，再运行 iOS debug 无签名构建做回归验证。

## 验收

- 元数据 `episodes: null` 的剧集进入视频页后不再立即显示“没有可播放的视频地址”。
- 默认请求第 1 集，HLS 地址解析成功后自动播放并循环。
- 点击免费观看/选集可切换服务返回的 episode number。
- 播放会话在页面离开时释放；播放服务异常时显示可理解的重试提示。
