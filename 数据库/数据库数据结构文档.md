## 2. 数据库用途和边界

该数据库用于保存剧库快照、浏览器身份、追剧记录、下载任务以及榜单的预留结构。

当前系统的核心数据链路如下：

```text
9000 原始剧库服务
        │ 导入 Drama[]
        ▼
    dramas ─────── library_sources
        │
        ├── following ───── viewers
        └── download_tasks ─ viewers
```

逻辑关联目前由应用代码维护，数据库没有声明外键约束。这样可以保留上游数据的灵活性，但删除或清理数据时需要由应用或维护脚本保证引用关系。

## 4. 表结构

### 4.1 `dramas`：剧集主表

保存剧集的完整原始 JSON，同时将常用查询字段拆出为独立列。`payload` 是数据完整性兜底字段，新增上游字段时不需要立刻修改表结构。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `id` | `VARCHAR(128)` | 是 | 无 | PK | 应用层唯一剧集 ID，例如 `hongguo:123` |
| `source` | `VARCHAR(32)` | 是 | `hongguo` | `idx_dramas_source_title`、`idx_dramas_source_id` | 站源标识，当前为 `hongguo` |
| `source_id` | `VARCHAR(96)` | 是 | 无 | `idx_dramas_source_id` | 上游站源内的剧集 ID |
| `vip` | `BOOLEAN` | 否 | `NULL` | 无 | 是否 VIP；MySQL 实际类型为 `TINYINT(1)` |
| `title` | `VARCHAR(512)` | 是 | `''` | `idx_dramas_source_title` | 展示标题及排序字段 |
| `name` | `VARCHAR(512)` | 是 | `''` | 无 | 兼容上游名称字段 |
| `description` | `TEXT` | 是 | `''` | 无 | 剧集描述，对应 API 的 `desc` |
| `intro` | `TEXT` | 是 | `''` | 无 | 剧集简介 |
| `category_name` | `VARCHAR(128)` | 是 | `''` | 无 | 归一化后的分类名称 |
| `tags_text` | `TEXT` | 是 | `''` | 无 | 标签拼接文本，用于搜索；原始标签仍保存在 `payload` |
| `total_episode` | `INT` | 否 | `NULL` | 无 | 归一化后的总集数 |
| `release_status` | `VARCHAR(32)` | 是 | `''` | 无 | 上线/更新状态 |
| `payload` | `JSON` | 是 | 无 | 无 | 完整 `Drama` JSON |
| `created_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 首次写入时间 |
| `updated_at` | `TIMESTAMP` | 是 | 当前时间 | `idx_dramas_updated_at` | 最近更新时间，更新时自动刷新 |

索引：

- 主键：`PRIMARY KEY (id)`
- `idx_dramas_source_title (source, title)`：按站源和标题读取、排序
- `idx_dramas_source_id (source, source_id)`：按站源定位上游剧集
- `idx_dramas_updated_at (updated_at)`：按更新时间查询

### 4.2 `library_sources`：站源状态表

每个数据站源一行，用于记录剧库是否可用、当前数量和版本号。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `source` | `VARCHAR(32)` | 是 | 无 | PK | 站源标识 |
| `status` | `VARCHAR(32)` | 是 | `ready` | 无 | 当前状态，例如 `ready` |
| `count` | `INT` | 是 | `0` | 无 | 该站源的剧集数量 |
| `error_message` | `VARCHAR(1024)` | 否 | `NULL` | 无 | 最近一次错误信息 |
| `updated_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 状态更新时间 |
| `revision` | `BIGINT UNSIGNED` | 是 | `1` | 无 | 数据版本号，每次源数据更新递增 |

### 4.3 `viewers`：浏览器身份表

对应 API 的 `juku_viewer_id` HttpOnly Cookie。它不是用户账号表，不保存登录账户或密码。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `id` | `VARCHAR(128)` | 是 | 无 | PK | 浏览器身份 ID |
| `created_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 首次出现时间 |
| `updated_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 最近访问或写入时间 |

### 4.4 `following`：追剧和收藏表

按浏览器身份保存剧集的收藏、已看状态和已知集数基准。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `viewer_id` | `VARCHAR(128)` | 是 | 无 | 复合主键、`idx_following_viewer_updated` | 浏览器身份 ID |
| `drama_id` | `VARCHAR(128)` | 是 | 无 | 复合主键 | 剧集 ID |
| `source` | `VARCHAR(32)` | 是 | `hongguo` | 无 | 站源 |
| `title` | `VARCHAR(512)` | 是 | `''` | 无 | 写入时缓存的剧名 |
| `category` | `VARCHAR(128)` | 是 | `''` | 无 | 写入时缓存的分类 |
| `saved` | `BOOLEAN` | 是 | `FALSE` | 无 | 是否收藏；实际类型为 `TINYINT(1)` |
| `completed` | `BOOLEAN` | 是 | `FALSE` | 无 | 是否标记为已看完 |
| `known_episodes` | `INT` | 是 | `0` | 无 | 用户确认时记录的集数基准 |
| `added_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 首次加入追剧时间 |
| `updated_at` | `TIMESTAMP` | 是 | 当前时间 | `idx_following_viewer_updated` | 最近修改时间 |

主键：`PRIMARY KEY (viewer_id, drama_id)`。同一浏览器身份对同一剧集只有一条记录。

### 4.5 `playback_history`：播放历史预留表

用于保存浏览器身份在某部剧上的播放状态快照，由 9010 API 的 `/api/ui/history` 读写。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `viewer_id` | `VARCHAR(128)` | 是 | 无 | 复合主键、`idx_history_viewer_watched` | 浏览器身份 ID |
| `drama_id` | `VARCHAR(128)` | 是 | 无 | 复合主键 | 剧集 ID |
| `payload` | `JSON` | 是 | 无 | 无 | 播放进度或播放状态快照 |
| `watched_at` | `TIMESTAMP` | 是 | 当前时间 | `idx_history_viewer_watched` | 最近观看时间 |

主键：`PRIMARY KEY (viewer_id, drama_id)`。同一浏览器身份对同一剧集只保留最近一次观看状态。

### 4.6 `download_tasks`：下载任务表

保存下载提交记录。当前项目只负责持久化任务，不启动实际下载 worker、FFmpeg 或 Emby 处理流程。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|
| `id` | `VARCHAR(128)` | 是 | 无 | PK | 下载任务 ID |
| `viewer_id` | `VARCHAR(128)` | 是 | 无 | `idx_tasks_viewer_updated` | 提交任务的浏览器身份 |
| `drama_id` | `VARCHAR(128)` | 是 | 无 | `idx_tasks_drama` | 要下载的剧集 ID |
| `title` | `VARCHAR(512)` | 是 | `''` | 无 | 创建任务时缓存的剧名 |
| `quality` | `INT` | 是 | `0` | 无 | 清晰度等级，API 限制为 0-10 |
| `status` | `VARCHAR(32)` | 是 | `queued` | 无 | 初始状态为排队 |
| `progress` | `INT` | 是 | `0` | 无 | 进度百分比，API 响应范围为 0-100 |
| `payload` | `JSON` | 否 | `NULL` | 无 | 任务扩展信息预留 |
| `created_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 创建时间 |
| `updated_at` | `TIMESTAMP` | 是 | 当前时间 | 无 | 更新时间 |

### 4.7 `ranking_boards`：榜单目录预留表

保存榜单目录及其完整上游响应。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |

### 4.8 `ranking_items`：榜单条目预留表

保存榜单分页中的剧集排序信息。

| 字段 | 类型 | 必填 | 默认值 | 索引 | 说明 |
|---|---|---|---|---|---|

| `page` | `INT` | 是 | 无 | 复合主键 | 榜单页码 |

## 5. `dramas.payload` JSON 结构

`dramas.payload` 保存 API 返回的完整剧集对象，对应 Go 模型 `Drama`。稳定的核心字段如下：

| JSON 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 剧集唯一 ID |
| `source` / `sourceId` | string | 站源和上游 ID |
| `title` / `name` | string | 标题和名称 |
| `desc` / `intro` | string | 描述和简介 |
| `vip` | boolean/null | VIP 标记 |
| `cover`、`coverUrl`、`image`、`poster` 等 | any | 兼容不同上游封面字段 |
| `totalEpisode`、`episodeCount`、`episodes` 等 | any | 兼容不同上游集数字段 |
| `category`、`categoryName`、`typeName` | string | 分类及类型字段 |
| `score`、`views`、`heat` | string | 评分、播放量、热度 |
| `onlineDate` | string | 上线日期 |
| `tags` | string[] | 标签列表 |
| `releaseStatus` | string | 发布状态 |
| `sortMetadata` | object | 封面检查和排序元数据 |

写入 `dramas` 时，应用层会从 JSON 中生成查询列：

- `source`：缺省为 `hongguo`。
- `source_id`：当输入为空时，从 `id` 去除 `source:` 前缀得到。
- `category_name`：按 `categoryName`、`category_name`、`category` 顺序取第一个非空值。
- `tags_text`：将 `tags` 数组以空格拼接，用于模糊搜索。
- `total_episode`：按多个兼容字段提取第一个有效集数。
- `release_status`：来自 `releaseStatus`。

## 6. API 与数据表映射

| API | 主要数据操作 | 说明 |
|---|---|---|
| `GET /api/ui/viewer` | 写入 `viewers` | 首次访问创建 `juku_viewer_id` Cookie；站源列表当前由代码返回 `hongguo` |
| `GET /api/ui/dramas` | 读取 `dramas`、`library_sources` | 返回剧库快照、站源状态和 revision |
| `GET /api/ui/search` | 读取 `dramas` | 在标题、名称、描述、简介、分类和标签文本中搜索 |
| `POST /api/ui/dramas/refresh` | 读取 `dramas` | 返回已持久化的单部剧资料，不访问上游刷新 |
| `POST /api/ui/cover/repair` | 读取 `dramas.payload` | 从已保存的封面字段中返回可用地址 |
| `GET /api/ui/following` | 读取 `viewers`、`following` | 返回当前浏览器的追剧记录 |
| `POST /api/ui/following` | 读取 `dramas`，写入 `viewers`、`following` | 保存收藏、已看和已知集数基准 |
| `GET /api/ui/history` | 读取 `viewers`、`playback_history` | 返回当前浏览器的观看记录，按最近观看时间倒序 |
| `POST /api/ui/history` | 读取 `dramas`，写入 `viewers`、`playback_history` | 保存剧集、集数、播放位置和时长 |
| `POST /api/ui/download` | 写入 `download_tasks` | 只创建排队任务，不启动实际下载 worker |
| `GET /api/ui/rankings` | 当前不读表 | 返回榜单空占位结果；`ranking_boards`、`ranking_items` 为预留结构 |
| `POST /api/ui/recommendations` | 当前不读表 | 返回空推荐占位结果 |
| `GET /api/ui/image` | 不读数据库 | 校验并重定向到 HTTP/HTTPS 图片地址 |
| `GET /health` | 不读数据库 | 仅表示 HTTP 进程可响应，不代表数据库连接状态 |

## 7. 数据写入和更新规则

1. 剧集使用 `id` 做幂等 Upsert；重复导入同一 `id` 会更新现有记录，不产生重复剧集。
2. 每次剧集 Upsert 后，会按 `source` 重新统计 `dramas` 数量，并更新 `library_sources.count` 和 `revision`。
3. 搜索使用结构化列，不直接对整个 JSON `payload` 做全文搜索。
4. 追剧记录使用 `(viewer_id, drama_id)` 保证同一浏览器对同一剧集只有一条状态。
5. 下载任务使用独立随机 ID；当前创建后状态为 `queued`、进度为 `0`。
6. 临时播放地址、`stoken` 和密码不写入数据库。完整上游信息仅在允许的 `payload` JSON 中保存。
7. 当前实现没有外键约束；删除剧集不会自动删除追剧、历史或下载记录。

## 9. 变更注意事项

- 新增上游剧集字段时，优先先保存在 `dramas.payload`，只有需要筛选、排序或索引时才新增结构化列。
- 修改结构化列的归一化规则时，需要同步检查导入器、API 搜索和 OpenAPI 字段说明。
- 修改 `following`、`download_tasks` 的字段时，需要同步检查 API 请求/响应模型和 SQL Upsert 语句。
- 如果未来启用榜单或播放历史，需要补充对应 Store 接口、API 行为和数据清理策略，并考虑是否增加外键或定期孤儿数据清理。
- `GET /health` 当前只验证 HTTP 可用性；需要确认数据库时，应同时验证 `/api/ui/dramas` 或直接执行数据库连接检查。
